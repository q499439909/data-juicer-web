# Data-Juicer Agent 多用户 Web 设计

状态：需求确认稿
范围：测试阶段，Linux，2～3 个在线用户，3～4 个并发任务
产品名称：Data-Juicer Agent
副标题：智能数据处理工作台

## 1. 建设目标

为现有 `DJSessionAgent` 增加一个桌面 Web 应用，支持多用户隔离、Data-Juicer/Ray 任务执行和管理员观测。

本期只建设三个业务页面：

1. Agent 工作台
2. 任务中心
3. 运行与调用（管理员）

登录、注册和账号管理是辅助功能，不增加独立业务模块。暂不使用或修改 `qa-copilot`。

## 2. 已确认规则

### 2.1 用户与权限

- 用户可自行注册，注册后立即可用。
- 登录使用用户名和密码，密码只保存安全哈希。
- 登录状态使用 HttpOnly Cookie。
- 用户只能访问自己的会话、任务、上传文件、工作区和结果。
- 管理员可以访问、取消、重试和删除所有用户的会话、任务及结果。
- 管理员可在“运行与调用”页面的账号管理抽屉中启用/禁用用户、重置密码和调整管理员角色。
- 首个管理员通过 Linux 命令交互式创建，不在脚本或环境变量中保存密码。
- 将来接入现有数据平台时只替换身份适配器，三个业务页面及数据模型不变。

### 2.2 会话与任务

- 用户删除会话时只做隐藏，不删除关联任务和结果。
- 用户可通过“已隐藏”筛选恢复会话。
- 任务记录永久保留，不允许物理删除。
- 用户可以删除任务结果文件；删除结果不删除任务记录。
- Agent 生成方案后必须由用户确认，不能直接启动任务。
- 用户可以取消或重试自己的任务；管理员可以操作全部任务。

### 2.3 数据来源

首期支持：

- 单文件上传
- 多文件上传
- 文件夹上传
- ZIP/TAR 压缩包上传并安全解压
- 浏览用户自己的服务器工作区

数据平台来源通过 `DatasetProvider` 接口预留。没有可用适配器时，前端不显示“平台数据集”入口。

上传文件不限制扩展名，但 Agent/任务在使用前需要检查是否可以处理。压缩包必须防止路径穿越、软链接逃逸和解压炸弹。

### 2.4 工作区

普通用户不能访问任意服务器绝对路径，只能访问自己的工作区：

```text
workspaces/{user_id}/
  uploads/
  datasets/
  conversations/
  tasks/
  outputs/
```

管理员可通过后台访问全部用户工作区。所有服务端路径由后端生成并校验，不能直接信任浏览器提交的路径。

不制作独立 Logo，首期使用 `Data-Juicer Agent` 文字标识和简洁的数据叶片图形。

## 4. 辅助界面：登录与注册

登录页不是业务主页，采用居中的白色卡片：

- 用户名
- 密码
- 登录按钮
- “注册账号”入口

注册弹窗包含：

- 用户名：唯一，创建后不可修改
- 显示名称：允许后续修改
- 密码
- 确认密码

注册后自动登录并进入 Agent 工作台。连续登录失败需要短时间限流；禁用用户不能登录或继续使用已有会话。

## 5. 页面一：Agent 工作台

### 5.1 页面目标

让用户在一个页面内完成选择数据、与 Agent 沟通、确认方案、启动任务和查看结果。

### 5.2 布局

采用三栏布局：

```text
┌──────────────┬─────────────────────────────┬───────────────────┐
│ 会话列表     │ Agent 对话                  │ 数据与产物        │
│ 260 px       │ 自适应主区域                │ 340 px            │
│              │                             │                   │
│ 新建/搜索    │ 消息、工具进度、确认执行    │ 数据源/方案/结果  │
└──────────────┴─────────────────────────────┴───────────────────┘
```

左右栏支持折叠，中间对话区始终是视觉中心。

### 5.3 左栏：会话列表

- “新建会话”主按钮。
- 按标题搜索会话。
- 筛选“进行中、全部、已隐藏”。
- 每个会话显示标题、更新时间和关联任务状态。
- 更多菜单支持重命名、隐藏和恢复。
- 普通列表不显示已隐藏会话。
- 页面刷新或重新登录后恢复最近打开的会话。

会话所有权由后端校验，不能依赖前端过滤。

### 5.4 中栏：Agent 对话

- 用户消息和 Agent 回复采用清晰的左右区分，不使用强烈气泡色。
- Agent 回复支持流式显示、复制和重新生成。
- 生成期间显示“停止”按钮。
- 工具执行过程显示为折叠时间线，例如：
  - 正在检查数据集
  - 正在检索算子
  - 正在生成处理方案
  - 方案校验完成
- 默认不展示模型内部思考内容。
- 错误信息说明失败阶段，并提供重试入口。
- 当 Agent 生成可执行方案后，在对话底部展示“执行确认卡片”。

### 5.5 执行确认卡片

卡片必须在任务启动前由用户确认，包含：

- 数据来源及大小
- 文件数量
- Data-Juicer 算子摘要
- 输入和输出位置
- 系统识别的 CPU/GPU 资源需求
- 调度说明
- 查看完整 YAML 配置
- “确认执行”和“返回修改”按钮

用户侧统一显示“系统自动调度”，不要求用户理解普通执行和 Ray。后端仍保留两种执行适配器，由调度层根据算子兼容性及 CPU/GPU 需求选择；管理员详情可查看实际后端。并发上限、用户上限和资源容量作为服务器配置，不写死在前端。

### 5.6 右栏：数据与产物

右栏包含三个页签：

#### 数据

- 上传单文件或多文件。
- 上传整个文件夹。
- 上传 ZIP/TAR，展示解压进度和失败原因。
- 浏览当前用户工作区，支持目录进入、搜索和选择。
- 展示文件名、类型、大小、更新时间。
- `DatasetProvider` 可用时自动增加“平台数据集”入口。

#### 方案

- 展示 Agent 当前生成的处理方案。
- 显示算子数量、执行方式和校验状态。
- 支持查看与复制 YAML。
- 不允许用户在首期直接编辑 YAML；需要修改时通过对话告诉 Agent，避免界面和 Agent 状态不一致。

#### 产物

- 展示当前会话关联任务的结果。
- 支持查看文件信息、预览可识别的文本/图片/表格、下载和删除结果。
- 不支持预览的文件只提供下载。
- 删除需要二次确认，并明确任务记录会永久保留。

## 6. 页面二：任务中心

### 6.1 页面目标

集中管理统一调度的数据处理任务。普通用户只看到自己的任务；管理员可查看全部任务。

### 6.2 顶部统计

使用四个紧凑卡片：

- 运行中
- 排队中
- 今日成功
- 今日失败

### 6.3 筛选与列表

支持筛选：

- 关键词
- 状态
- 调度后端（管理员或诊断场景）：普通执行/Ray
- 创建时间
- 是否仍有结果文件
- 管理员额外支持用户筛选

任务列表字段：

- 任务名称/ID
- 用户（管理员可见）
- 数据集摘要
- CPU/GPU 资源申请
- 状态与进度
- 创建时间
- 运行时长
- 结果状态
- 操作

状态包括：排队中、正在启动、运行中、成功、失败、取消中、已取消。排队任务额外显示预计资源队列位置以及等待 CPU、等待 GPU、用户并发限制、全局并发限制或 Ray 未就绪等原因。

### 6.4 任务操作

- 排队中或运行中：取消。
- 失败或已取消：重试。
- 成功：查看结果、下载结果、删除结果。
- 所有任务：进入来源会话。
- 重试时保留原任务记录，并创建新的任务 ID，通过 `retry_of` 关联。
- 任务记录永久保留，因此页面不提供“删除任务记录”。

### 6.5 持久化公平调度

- SQLite 是任务队列和状态的唯一事实来源，路由只入队并唤醒调度器。
- 默认全局最多 3 个运行任务，每用户最多 1 个，可由环境变量调整。
- 不同用户轮询调度，用户内部按提交顺序执行；资源不满足的用户不会阻塞其他用户。
- 普通执行和 Ray 共用 CPU/GPU 资源账本，避免相互抢占。
- 调度主节点使用数据库租约，多个 Web Worker 不会重复派发任务。
- Web 重启后自动恢复等待任务和过期派发任务；Ray 任务按 Job ID 恢复监控，普通任务通过独立包装进程及原子退出记录恢复监控。
- Linux 同机 Ray 不可用且启用自动管理时，Web 尝试执行 `ray start --head`。

### 6.6 任务详情抽屉

点击任务后从右侧打开详情抽屉，包含：

- 基本信息：用户、状态、执行方式、创建和完成时间。
- 资源信息：CPU、GPU、内存及 Ray job ID。
- 数据信息：输入来源、文件数、大小和输出位置。
- 配置：实际执行的 Data-Juicer YAML，只读展示。
- 时间线：提交、排队、启动、关键阶段和结束。
- 日志：持续追加、支持搜索和自动滚动暂停。
- 错误：失败原因、错误阶段和完整堆栈；普通用户隐藏敏感服务器路径和凭据。
- 结果：文件列表、预览、下载和删除。

## 7. 页面三：运行与调用（管理员）

### 7.1 页面目标

用于查看所有用户的 Agent 运行、模型调用、工具调用、Data-Juicer/Ray 执行情况，并完成管理员操作。

### 7.2 顶部总览

展示当前时间范围内：

- 活跃用户数
- Agent 运行次数与成功率
- 本机/Ray 任务数量
- 平均响应时间和 P95
- 模型输入/输出 Token
- 工具调用次数
- 失败数量

### 7.3 运行列表

支持筛选：

- 用户
- 时间范围
- 会话 ID
- 任务 ID
- 运行状态
- 模型
- 工具
- 本机/Ray
- 错误类型

列表字段：

- 运行 ID
- 用户
- 会话
- 用户问题摘要
- 状态
- 模型/执行方式
- Token
- 总耗时
- 开始时间

### 7.4 运行详情

点击运行后进入详情抽屉或详情视图：

- 用户完整问题和 Agent 完整回答。
- Agent 运行时间线。
- 模型调用参数、Token、耗时和返回状态。
- 工具名称、完整参数、返回结果和耗时。
- Data-Juicer 配置与算子列表。
- 本机进程或 Ray job 信息。
- 完整日志和错误堆栈。
- 关联数据集、任务、结果和会话。

管理员可以查看完整内容，但以下操作必须写审计记录：

- 查看用户完整对话
- 查看工具完整参数或结果
- 下载用户结果
- 取消或重试用户任务
- 删除用户结果
- 隐藏或恢复用户会话
- 修改用户账号或角色

### 7.5 管理操作

管理员可在运行详情或关联任务中：

- 取消任务
- 按原配置重试
- 修改为本机/Ray 后重试
- 删除结果文件
- 隐藏/恢复会话

任务记录和管理员审计记录不可从界面删除。

### 7.6 账号管理抽屉

从页面右上角打开，不新增业务页面：

- 用户名、显示名称、角色、状态、注册时间、最近登录。
- 搜索用户。
- 禁用/启用账号。
- 交互式设置临时密码，用户下次登录时可被要求修改。
- 提升为管理员或取消管理员。
- 防止管理员取消自己的最后一个管理员身份。

## 8. 关键数据状态

### 8.1 会话

```text
active → hidden → active
```

隐藏只影响普通会话列表，不删除消息、任务和结果。

### 8.2 任务

```text
awaiting_confirmation
  → queued
  → running
  → succeeded | failed | cancelling → cancelled
```

重试创建新任务记录，旧记录保持不变。

### 8.3 结果

```text
available → deleting → deleted
```

任务记录保留结果曾经存在的元数据、删除时间和操作者，但不保留已删除文件内容。

## 9. 最小侵入技术方案

### 9.1 与现有 Agent 的关系

- Web 直接使用 `DJSessionAgent`，不经过 `qa-copilot`。
- 每个活动会话使用独立 Agent 状态，禁止多个用户共享可变 Agent 实例。
- 每次访问会话、任务、文件和结果前都在后端验证 owner。
- 工作目录由后端按用户和任务分配。
- 建议只修改一个旧文件：为 `DJSessionAgent` 增加公开的状态快照导出/恢复接口。
- CLI/TUI、规划、检索、工具和执行逻辑保持不变。

`codebase-design` 对本方案的影响是：认证、数据平台、执行选择和 Agent 状态各自形成小接口的深模块，复杂校验集中在实现中，避免调用方自行拼 `user_id` 或文件路径。

### 9.2 可替换接口

#### IdentityProvider

统一返回当前用户、角色和状态。首期使用内置账号适配器；以后增加平台适配器。

未配置可信适配器时不得退化成共享匿名用户。

#### DatasetProvider

提供当前用户可见的数据集列表和可用数据引用。没有适配器时返回 unavailable，前端隐藏入口。

#### ExecutionPolicy

根据算子兼容性、CPU/GPU、数据大小、文件数量和 API 并发要求返回推荐执行方式、原因和不可选方式。

#### AgentSnapshotStore

保存和恢复 `DJSessionAgent` 状态；调用方不读取 Agent 私有字段。

### 9.3 存储

测试版使用自动初始化的 SQLite 保存：

- 用户与密码哈希
- 会话和消息
- Agent 状态快照
- 任务记录
- 模型/工具调用
- 文件和结果元数据
- 管理员审计记录

任务日志和文件内容保存在用户工作区，数据库只保存受控路径和元数据。SQLite 开启 WAL 并建立归属索引，足以支持当前 2～3 个在线用户和 3～4 个并发任务。后续用户量扩大时，可在存储接口后替换为 PostgreSQL；首期不额外引入 Redis。

## 11. Linux 测试部署

不需要额外的发布包目录。交付内容就是一个旧文件和一个新增目录：

```text
data_juicer_agents/capabilities/session/orchestrator.py  # 修改后的旧文件
agent_web/                                               # 整体新增
```

上传完成后，在项目根目录运行 `bash agent_web/install.sh`、创建管理员，再用 `bash agent_web/start.sh` 启动即可。默认采用手动命令启动，不假设 Docker 或 systemd。Ray 地址、工作区根目录、监听地址等通过 `agent_web/.env` 配置；SQLite 和工作区会自动创建。

旧文件处理规则：

1. 先备份服务器上的 `orchestrator.py`。
2. 如果服务器项目版本与本次开发基线一致，可直接用修改后的文件覆盖；版本不同则先比较差异，不直接覆盖。
3. 将新增的 `agent_web/` 目录整体复制到项目根目录；首次部署不会覆盖原业务目录。
4. 按 `agent_web/DEPLOY_ZH.md` 安装、创建管理员并启动。
5. 访问 `/health`，再用两个测试账号验证会话、文件和任务互相不可见。
6. 如果启动检查失败，恢复已备份的 `orchestrator.py` 并移走 `agent_web/` 即可回滚；SQLite 和工作区数据另行保留备份。

## 12. 验收标准

### 12.1 用户隔离

- 用户 A 不能通过修改会话、任务、文件或结果 ID 访问用户 B 的资源。
- 两个用户同时运行时不共享 Agent memory、工作目录、任务状态和结果。
- 上传和解压不能写出用户工作区。
- 禁用用户无法登录或继续调用接口。

### 12.2 功能

- 注册、登录、退出和管理员重置密码可用。
- 会话可新建、搜索、隐藏、筛选和恢复。
- 四种上传方式可用。
- Agent 可生成方案，用户确认后创建任务。
- 本机和 Ray 均可执行，自动推荐可解释，用户可修改可用选项。
- 任务可取消、重试、查看日志和删除结果。
- 任务记录在结果删除、会话隐藏后仍可查询。
- 管理员可以查看完整运行与调用信息并管理所有任务和账号。

### 12.3 审计与安全

- 管理员敏感查看和管理操作都有审计记录。
- 密码、Cookie、密钥和 Authorization 不进入日志。
- 用户无法提交任意宿主机路径。
- 任务和日志页面安全显示恶意文本，不执行其中的 HTML 或脚本。
